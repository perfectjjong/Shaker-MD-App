# Price Q&A 정확도 측정 — 다음 세션 작업지시서

작성 2026-09-04. **템플릿 밖(자유 질의) 정확도가 한 번도 측정된 적 없다**는 것이 유일한 목표다.

## 지금 상태 (이걸 다시 조사하지 말 것)

- 템플릿에 걸리는 18문항: 매일 07:00 회귀, 전부 통과. **이건 이미 됐다.**
- 템플릿에 안 걸리는 질문: AI가 매번 SQL을 짓고 **아무도 검증하지 않는다.** ← 이번 작업 대상
- 커버리지 게이트 있음: 템플릿이 조건을 못 담으면 자유 질의로 넘긴다(`match_template`).
  즉 **넘어간 질문이 많다** — 그 정확도가 곧 Q&A의 실제 정확도다.

## 절대 하지 말 것 (지난 세션 실패 원인)

1. **내가 지어낸 질문으로 평가하지 말 것.** 그렇게 만든 "100% 통과"가 오답을 덮었다.
2. **뷰로 뷰를 검증하지 말 것.** 정답은 raw 테이블(`products`·`price_snapshots`)에서 직접 구한다.
3. **총합·행수만 보지 말 것.** 조건 준수를 **전 행** 검사한다(`chk_attr_all` 등 기존 검사기 재사용).
4. 실패가 나오면 **검사기를 고치지 말 것.** 제품을 고친다.

## 단계

### 1) 질문 은행 (목표 40~60개) — 실제 발화에서만 뽑는다
- 텔레그램: `/home/ubuntu/.hermes/state.db` → `messages` (role='user' 924건, 가격 관련 96건).
  FTS(`messages_fts`) 사용 가능.
- Claude 세션: `~/.claude/projects/-home-ubuntu/*.jsonl` (103개). 이 세션 파일에 09-02~03 질문 있음.
- 뽑은 뒤 **가격 DB로 답할 수 있는 것만** 남긴다(판매량·매출·점유율은 `unanswerable()` 대상).

### 2) 정답 만들기 — 손으로 짠 SQL
질문마다 기대 SQL을 손으로 짜고 결과를 파일로 굳힌다. 이게 유일한 정답 기준.
애매한 질문(해석이 갈리는 것)은 **정답을 정하지 말고 '모호' 라벨** → 템플릿·되묻기 대상으로 분류.

### 3) 러너 — AI 생성 SQL vs 정답 대조
`qa_regression.py` 골격 재사용하되 **템플릿을 우회**해 AI 경로만 측정한다.
산출: 정확도 %, 실패 목록, 실패 유형.

### 4) 실패 분류 → 조치
| 유형 | 조치 |
|---|---|
| 스키마 프롬프트가 부족 | `SQL_SYS` 보강 |
| 매번 해석이 갈림(모호) | 템플릿 승격 or 되묻기 |
| DB에 없는 정보 | `unanswerable()` 에 추가 — 지어내지 말고 못 한다고 답한다 |
| 조건 무시 | 커버리지 게이트 확장 |

### 5) 독립 검증
2차 모델(Fable 서브에이전트)에게 **적대적으로** 표본 15건 재검. 내가 내 답을 채점하지 않는다.

### 6) 형님 표본 검수 (마지막)
정확도 숫자와 함께 **실패 사례 5건 원문**을 보여드린다. 숫자만 보고하지 말 것.

### 7) 게이트화
측정 결과를 기준선으로 저장 → 이후 자유 질의 정확도가 떨어지면 알림.

## 완료 기준
"자유 질의 정확도 N%" 를 **근거(질문 목록·정답 SQL·실패 사례)와 함께** 말할 수 있을 때. 그 전엔 미완이다.
